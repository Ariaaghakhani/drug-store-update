# composables/

## Purpose
Shared Composition API logic for the pharmacy storefront's user panel area: role-based dashboard data fetching (customer/admin/owner), navigation/tab config per role, a toast-notification wrapper, a role-permission updater, and Persian (`fa-IR`) number/currency formatting helpers.

## Key files
- `useAdminDashboard.js` — wired (Phase 6) to BACK's real `DashboardController` via [`services/api/analytics.js`](../services/api/CLAUDE.md): `summary` (`getDashboardSummary`), `lowStock` (`getLowStock`), `expiringGoods` (`getExpiringGoods`). Order queue and prescription review queue have no BACK endpoint — left as TODO comments, intentionally unimplemented.
- `useAppToast.ts` — wraps Nuxt UI's `useToast()`, adding `success`/`error`/`info`/`warning` helpers with preset colors/icons.
- `useCustomerDashboard.js` — **wired to real data (2026-10-27)**: a single `$api.analytics.getCustomerDashboardSummary()` call (`customer-dashboard-summary` `useAsyncData` key), with `stats`/`orders`/`prescriptions`/`reorderItems` as `computed()`s deriving from the one `summary` response instead of 5 independent mock fixtures. `orders` maps BACK's `status`(PAID/PENDING/...)+`fulfillmentStatus`(SHIPPED/READY_FOR_PICKUP/DELIVERED/null) pair down to the 4-stage `pending/packaging/shipping/delivered` string `OrderTracking.vue` expects, via `mapOrderStage()` — an approximation for terminal/exception fulfillment states (`DELIVERY_FAILED`/`RETURNED_TO_STORE`/`LOST`/`DAMAGED`/`NOT_COLLECTED`), which all fall into `'packaging'` since the component has no slot for them. **No `reminders`/`remindersPending` returned at all** — BACK's `refillReminders` is always `[]` (no refill-reminder feature), so the field and its consuming `RefillReminders.vue` component were dropped rather than kept as dead mock UI.
- `useFormat.js` — pure formatting helpers for counts, prices, thousands, and days, all using `fa-IR` locale.
- `useOwnerDashboard.js` — **fully wired (2026-10-27)**: `userActivityChart`/`categoryChart` as before, plus `revenueSummary` (`getRevenueSummary`), `salesTrendChart` (`getSalesTrendChart`), `topProducts` (`getTopProducts`), `staffActivity` (`getStaffActivity`) — each its own `useAsyncData` key following the same `{data, pending}`-pair pattern, all staff-with-dashboard-access only.
- `useUpdateRolePermission.ts` — updates a role's permission in [`stores/roles.ts`](../stores/CLAUDE.md) and calls a no-op `syncToApi` stub.
- `useUserPanelTabs.js` — **migrated from `.ts`; panel menu is permission-driven (2026-10-29)**. Customers always get the static customer list. Staff: `refreshMenus()` calls `POST api/auth/me/permissions` `{allowed:true, actions:['READ']}` (backend FRONTEND_FEATURES_BY_USER.md §C0), stores distinct `{module, action}` in `userStore.permissions`, and a registry menu (`utils/panelMenus.js`, `modules: [...]`) shows when the user holds READ on any of its BACK modules (`always: true` menus — dashboard, profile — show for everyone, since the guard redirects to the dashboard). Menus with a `flag` (wallet/wishlist) also need that `GET api/store-profile` boolean on; route *access* ignores flags (the profile loads async). If permissions are missing/empty/failed the old per-role lists (`FALLBACK_MENUS_BY_ROLE`) apply; `refreshMenus()` never throws.
- `useStoreProfile.js` — **new (2026-10-29)**: shares `GET api/store-profile` flags app-wide via `useState`; optional features (`wishlistEnabled`, `walletEnabled`, `stockAlertsEnabled`, ...) read OFF until it loads, `orderingEnabled` reads ON. **C12a (2026-11-11)**: `refresh()` drops the cached profile and fetches it again; the settings editor calls it after a save in `STOREFRONT_FEATURES`/`STORE_PROFILE`/`ORDER`, and the store type page calls it after a save.
- `useNotifications.js` — **new (2026-10-29)**: shared inbox state via `useState` (`unread`, `recent` = latest 6 for the bell, `recentLoading`/`recentLoaded`) + `refreshUnread`, `loadRecent`, `markRead(item)` (optimistic, also updates the bell copy), `markAllRead`, `onPushReceived` (called by `plugins/notifications.client.js`), `startPolling`/`stopPolling` (one shared 60s timer, skipped while the tab is hidden, the fallback when push is off/blocked), `reset` (logout).
- `usePushNotifications.js` — **new (2026-10-29)**: FCM web push. Lazily imports `firebase/app` + `firebase/messaging` (only `getToken`/`deleteToken`/`isSupported` are used), registers `public/firebase-messaging-sw.js` at Firebase's default scope `/firebase-cloud-messaging-push-scope` (never clashes with the PWA's workbox SW at `/`), and PUTs the token to BACK. Returns `{configured, supported, permission, token, optedOut, enabled, busy, enable(), sync(), disable({optOut})}`. `enable()` prompts (call from a click); `sync()` silently re-registers on app load and on login (`plugins/notifications.client.js`) only if permission is `granted` and the user didn't opt out; registration failures only go to `console.warn('[Push] …')`; `disable()` unregisters (fire-first, capped at 1.5s so logout never hangs). Config from `runtimeConfig.public.firebase` — all blank means `configured: false` and the push UI hides itself.
- `useSeenTickets.js` — **new (2026-11-01)**: `{hasNewMessage(ticket, isStaff), markSeen(ticket)}`. Frontend-only "new message" state for tickets, in `localStorage['tickets.seen.<userId>']` as `{ticketId: lastMessageAt}` (BACK's own timestamp, so the client clock doesn't matter). Closed tickets are never marked.
- `useManagedUsers.js` — **new (2026-11-01)**: shared by the users list and detail pages. `{roles, staffRoleItems, staffRoleIdsOf(user), loadRoles(), mapUser(dto), setActive(user, active), setLocked(user, locked), setRoles(user, roleIds), formatDateTime(value)}`. Each action toasts its result and returns the updated mapped user, or `null` when BACK refused.
- `useStoreCategories.js` — **new (2026-11-02)**: shared category tree (`GET api/categories/tree?scope=PRODUCT`) via `useState`, returns `{tree, status, byId, load(force), available}`; `status` ∈ `idle|loading|ready|unavailable|failed`. 401/403 and an empty tree → `unavailable` (not an error), network/server errors → `failed`.
- `useAddToCart.js` — **new (2026-11-02)**: `{ addToCart(card) }` for `ProductCard`-shaped products; adds `toCartItem(card)` to the cart store and toasts the result (min-order quantity aware). A `hasVariants` card navigates to `/medications/{linkId}` instead, since a variant has to be chosen first.
- `useFileDownload.js` — **new (2026-11-10)**: `{ download(requestPromise, fileName), previewUrl(requestPromise) }` for wrappers called with `{ responseType: 'blob' }`. The file is `res.data` (Blob). `download` saves via an `<a download>` click and revokes the URL; `previewUrl` resolves to an object URL for inline preview (**the caller revokes it**, e.g. in `onBeforeUnmount`) or `null`. Both toast `خطا در دریافت فایل` on failure and never read `.message` from a blob error body.
- `usePagedList.js` — **new (2026-11-10)**: shared paging for panel lists. `fetchPage({ page, size })` gets the backend page (`page.value - 1 + backendBase`, BACK is 0-based) and returns the API promise (`res.data.data` = `PageResponse`). Optional `filters` (deep-watched) reset to page 1; page changes reload; a request counter drops stale responses. Loads on mount (client only). `forbidden` = the last error was a 403.
- `usePendingTerms.js` — **new (2026-11-10)**: `{terms, accepting, check, accept, clear}` over `useState('pending-terms')`. `check()` loads `$api.auth.getPendingTerms()` only when logged in (client only) and never throws (a failure means no dialog); `accept()` posts `acceptPendingTerms()`, clears the list and returns `true`/`false`. Consumed by `components/TermsPendingDialog.vue`.
- `usePasswordRules.js` — **new (2026-11-10, B9)**: store password policy from `$api.auth.getPasswordRules()` (`GET api/auth/password-policy`) over `useState('password-policy')`, loaded once. Until it loads, or if the call fails, the fallback is the old rule of at least 8 characters, so forms never break. `ruleList` is a computed of `{text, met}` for the password passed in (a ref or getter); rule texts are Persian with digits from `toLocaleString('fa-IR')`. `validate(password)` returns the first unmet rule text or `''`. **C12c (2026-11-11)**: the admin password-policy page clears this `useState('password-policy')` cache after a save, so the next read fetches the new rules. Consumed by `components/auth/RegisterStep.vue`, `ResetPasswordStep.vue` and `components/panel/security/ChangePasswordModal.vue`.
- `useModuleAccess.js` — **new (2026-11-10, S0a)**: `{canRead(module), canReadAny(modules)}` over `userStore.permissions` (BACK `{module, action}` READ grants). Empty or not loaded permissions → true (show the UI, let BACK answer 403), so a missing grant list never hides a screen.
- `useMyAvatar.js` — **new (2026-11-12)**: the logged-in user's own profile photo, shared via `useState` (`my-avatar-url`, `my-avatar-saving`) so the panel header and `/panel/profile` update together. `{url, saving, load(), change(file), remove(), reset()}` on `auth.getMyAvatar`/`changeMyAvatar`/`removeMyAvatar`; `load()` never throws (failure = initials), `change`/`remove` throw BACK's error; `changeWithFeedback(file)` / `removeWithFeedback()` wrap them with the file check and success/error toasts and are what the profile card and the panel header's account menu use. Also exports `avatarFileError(file)` (JPEG/PNG/WebP, 2 MB — BACK's limits, for a friendlier message).
- `useWorkflowTaskCount.js` — **new (2026-11-14, C19d)**: `{count, unavailable, refresh({force}), start(), stop(), reset()}` over `useState('workflow-task-count')` (`{mine, claimable, overdue}` from `$api.workflow.getTaskCount()`, or `null`). Only staff (not `customer`, user loaded) who pass `canRead('WORKFLOW_TASK')` are tracked. `refresh()` swallows errors: a 403/404 clears the count and sets `unavailable`, which stops every later `refresh()` for the session (`force: true`, used by the inbox page, retries); any other failure keeps the last count. `start()`/`stop()` share one 60 s timer (ref-counted like `useNotifications`) and skip ticks while the tab is hidden. `reset()` on logout. Consumed by `pages/panel.vue` (menu badge) and `pages/panel/tasks/*` (tab counts, refresh after actions).
- `useInfoDocuments.js` — **new (2026-10-29)**: loads a public text page (about/terms/privacy/returns) into `components/InfoDocument.vue`'s `documents` shape.
- `useMyBlogComments.js` — **new (2026-11-10, B7)**: `{mineIds, isMine(commentId), remember(commentId), forget(commentId), refresh()}`. Ids of blog comments this browser posted, in `localStorage['blog-my-comments:<userId>']` (array, capped at 200, oldest dropped). Every storage access is in try/catch; when storage throws, the ids live in a module-level memory copy for the session. `remember` takes the `id` from the `addComment` response and ignores a missing or non-numeric id. Consumed by `pages/blog/[slug].vue`, which shows «حذف» only on `isMine` comments. Stand-in until BACK returns a `mine` flag (BACKEND_REQUESTS §3).

## Public surface
- `useAdminDashboard()` → `{ summary, summaryPending, lowStock, lowStockPending, expiringGoods, expiringGoodsPending }` — `summary` is `DashboardSummaryDTO`-shaped (`totalUsers, totalGoods, stockValueAtPurchasePrice, stockValueAtSalePrice, lowStockCount`), `lowStock`/`expiringGoods` are arrays per BACK's `LowStockDTO`/`ExpiringGoodsDTO`. No order-queue/prescription-review-queue fields (no BACK endpoint).
- `useAppToast()` → `{ ...toast, success(title, description?, icon?), error(title, description?, icon?), info(title, description?, icon?), warning(title, description?, icon?) }`.
- `useCustomerDashboard()` → `{ stats, statsPending, orders, ordersPending, prescriptions, prescriptionsPending, reorderItems, reorderPending }` — all `computed()`s over one underlying `summary` `useAsyncData`, so every `*Pending` ref is actually the same `summaryPending`.
- `useFormat()` → `{ formatCount(n), formatPrice(amount), formatThousands(amount), formatDays(n) }`.
- `useOwnerDashboard()` → `{ userActivityChart, userActivityChartPending, categoryChart, categoryChartPending, revenueSummary, revenueSummaryPending, salesTrendChart, salesTrendChartPending, topProducts, topProductsPending, staffActivity, staffActivityPending }` — `userActivityChart` is `BarChartDTO`-shaped (`labels, values`; active/inactive **user** counts, not sales), `categoryChart` is `PieChartDTO`-shaped (`categoryIds, categories, counts`; goods-**by-category counts**, not revenue), `revenueSummary` is `{totalRevenue,periodRevenue,previousPeriodRevenue,revenueGrowthPercent,periodStart}`, `salesTrendChart` is `{labels,values,orderCounts}`, `topProducts`/`staffActivity` are arrays.
- `useUpdateRolePermission()` → `{ updatePermission(roleId, domain, action, value) }`.
- `useFileDownload()` → `{ download(requestPromise, fileName), previewUrl(requestPromise) }` (blob responses; see Key files).
- `usePasswordRules(passwordSource)` → `{ ruleList, validate(password), load() }` (see Key files).
- `useModuleAccess()` → `{ canRead(module), canReadAny(modules) }` (see Key files).
- `useWorkflowTaskCount()` → `{ count, unavailable, refresh({ force }), start(), stop(), reset() }` (see Key files).
- `usePagedList(fetchPage, { size = 20, filters, backendBase = 0 })` → `{ items, total, totalPages, page, loading, error, forbidden, reload }` — `page` is the 1-based UPagination ref; see Key files.
- `useUserPanelTabs()` → `{ getUserRole(), getRoleLabel() (2026-11-13: مدیر داروخانه / کارکنان داروخانه / مشتری, used by the panel header, its account menu and the profile card), getRoutesForRole(), getMenuItems(), hasAccessToRoute(path), getAccessiblePaths(), refreshMenus() }` — plain functions, not reactive refs (they read `userStore.permissions`/`currentUser` and the store profile, so calling them inside a `computed` is reactive). Menu items are `{key, id, label, icon, to, badge?}`.

- `useUserPanelTabs.js` → [`stores/user.js`](../stores/CLAUDE.md) (`useUserStore`, `currentUser?.roles` — a real backend role-name array, with `currentUser?.role` as a legacy/mock fallback, see Gotchas); consumed by the panel layout/sidebar/nav shared across `/panel/*` pages — see [`layouts/CLAUDE.md`](../layouts/CLAUDE.md) and [`pages/panel/CLAUDE.md`](../pages/panel/CLAUDE.md).
- `useAppToast.ts` → Nuxt UI's global `useToast()`; used anywhere user feedback is needed.
- `useCustomerDashboard.js` (2026-10-27) → [`services/api/analytics.js`](../services/api/CLAUDE.md) (`$api.analytics.getCustomerDashboardSummary`), one call backing all 4 derived fields.
- `useAdminDashboard.js` / `useOwnerDashboard.js` (Phase 6, Owner's dashboard-section calls extended 2026-10-27) → [`services/api/analytics.js`](../services/api/CLAUDE.md) (`$api.analytics`, via `useNuxtApp()`), each field backed by its own `useAsyncData` call, following `useCustomerDashboard.js`'s original `{data, pending}`-pair pattern. Consumed by [`components/dashboard/admin/AdminDashboard.vue`](../components/dashboard/CLAUDE.md) and [`components/dashboard/owner/OwnerDashboard.vue`](../components/dashboard/CLAUDE.md).
- `useFormat.js` is a leaf utility with no dependencies, used throughout panel/dashboard/product UI for Persian-formatted prices, counts, and day counts.
- `useUpdateRolePermission`'s `syncToApi` (no-op stub) remains the only composable in this module with no real backend call behind it — everything else now calls into `services/api/*`.

## Gotchas
- **TS/JS drift**: the project reverted from TypeScript to JavaScript (commit `209e98b`, "Revert from TS to JS"), but `useAppToast.ts` and `useUpdateRolePermission.ts` were never converted and remain `.ts` (`useUserPanelTabs` was migrated to `.js` on 2026-10-28). Same drift exists in [`stores/roles.ts`](../stores/CLAUDE.md). Any code depending on their type exports (`RolePermissions`, `Permission`, `RouteItem`, `UserRole`) is coupled to that lingering TS surface.
- `getUserRole()` defaults to `'admin'` (not `'customer'`) when nothing is recognized (no `roles` array and no legacy `role` string) — can over-grant admin-style nav items to unauthenticated/malformed sessions.
- **Fixed (2026-10-09): role-based menu wasn't applied at all for real logged-in users.** `getUserRole()` used to read a singular `userStore.currentUser?.role` string, but BACK's real `UserDTO`/`TokenResponse.user` (what `pages/login.vue::finalizeLogin` actually stores via `$auth.setUser`) has `roles: string[]` instead — backend role *names* (`ROLE_STORE_ADMIN`, `ROLE_CUSTOMER`, or a tenant-defined custom staff role name), not this composable's 3-value model at all. Since `currentUser.role` was always `undefined` for any real session, every logged-in user silently fell through to the `'admin'` default, regardless of actual role — the panel menu never varied by role in practice. `getUserRole()` now checks `currentUser.roles` first: `ROLE_STORE_ADMIN` → `'owner'` (BACK's only "full tenant access" role template), `ROLE_CUSTOMER` → `'customer'`, any other/custom role name → `'admin'` (every custom staff role created via `users.vue`'s create-user flow lands here — BACK has no fixed naming convention for staff role tiers, see `services/api/CLAUDE.md`'s `RoleDTO`). The old singular-`role`-string check is kept as a fallback only, for any seed/mock data that still sets it directly.
- `useAdminDashboard`/`useOwnerDashboard`/`useCustomerDashboard` use `useAsyncData` without an error callback — if `$api.analytics.*` rejects (e.g. 401/403), the data `ref` stays `null` and `*Pending` resolves to `false`; components render the empty state, not an error state. No retry/toast on failure yet.
- `useFormat.js` always appends Persian unit suffixes (`تومان`, `هزار تومان`, `روز`) baked into the returned string — callers can't strip the unit or reuse the formatter for non-Toman contexts.
- `useUpdateRolePermission`'s `syncToApi` is an empty async no-op — permission updates are currently applied only optimistically to the local Pinia store, with no real backend persistence yet (Users & Roles redesign is still pending a product decision — see `FRONTEND_API_TODO.md`).
- `useCustomerDashboard.js`'s `mapOrderStage()` is a lossy approximation: BACK's real lifecycle is an order `status` (PAID/PENDING/FAILED/CANCELLED) crossed with an independent `fulfillmentStatus` enum (8 values + null), but `OrderTracking.vue` only understands a 4-stage `pending→packaging→shipping→delivered` pipeline — every exception fulfillment state (failed delivery, returned, lost, damaged, not-collected) collapses into `'packaging'` rather than getting its own UI treatment.

- **Push state is module-level, not `useState`** (`usePushNotifications.js`): the server's `'unsupported'` permission would otherwise be serialized into the payload and override the browser's real `Notification.permission`. Push token + opt-out live in `localStorage` (`push.token`, `push.opted-out`).
- **Menu fallback caveat**: if `POST api/auth/me/permissions` fails or returns nothing, a narrow staff role (e.g. inventory) falls back to the 3-role `admin` list. Empty permissions mean "not loaded", not "no access" — otherwise the guard would bounce to `/panel/dashboard` forever.
