## 1. Global conventions (apply to every item)

### 1.1 Envelope and wrappers
- `apiCaller` returns `{data: <raw body>}`. ApiResponse bodies: payload = `res.data.data`. Raw bodies (NOT ApiResponse: `/api/import/goodsImport`, `/api/import/opening-stock`, `GET /api/admin/endpoint-permissions`, blobs) = `res.data`. Errors: `error.response.status`, `error.response.data.{errorCode,message}` (one level only).
- Wrapper style: `name(config) { return apiCaller.post('api/...', config) }` (see `services/api/ticket.js`); path ids are explicit args; one-line comment with the verified contract. GET with `config.params`. Multipart: caller builds `FormData` and passes `{data: formData}`. Register new files in `services/api/index.js` under the namespace named below (`import x from '@/services/api/x.js'` + `x: x(apiCaller)`).
- Paging: BACK is 0-based `page`/`size` (max 100) on GET lists. EXCEPTIONS (1-based): `POST api/purchase-orders/list`, `POST api/stock-movements/list`, `POST api/admin/audit/search`, `POST api/goods/filter`. `UPagination` is 1-based. `PageResponse` = `{content,totalElements,totalPages,page,size}`.
- 202 pending (A1 already toasts): staff writes may return `res.pending === true` (data is NOT the saved record). Every write handler: `const res = await ...; if (res.pending) { close modal; refetch; return }` and skip the own "saved" toast. 409 `workflow.action.pending` = show `error.response.data.message`. DTOs `OrderReturnDTO/OrderRefundDTO/PurchaseOrderDTO` carry `workflow:{pending,instanceId,status,action,activeSteps}`: when `workflow?.pending` show badge «در انتظار تأیید» and disable the gated button.
- 403 on load -> `PanelEmptyState` lock variant (no button). Failed load -> exclamation + retry (DESIGN_SYSTEM "Failed load"). Never render a failed fetch as "empty".
- Dates: send ISO (`YYYY-MM-DD` / `YYYY-MM-DDTHH:mm:ss`), show with `toLocaleDateString('fa-IR')` / `toLocaleString('fa-IR')` (already Jalali). Inputs use P3.
- Numbers on screen: `toLocaleString('fa-IR')`; numeric inputs: `UInput inputmode="numeric" dir="ltr"` + `parseQuantity` (`utils/inventoryMeta.js`), never `type=number`.
- Store-authored HTML is NEVER `v-html`: show with `htmlToText()` (`utils/storefrontGoods.js`); admin edits it in a `UTextarea` labelled "HTML".
- Code conventions (CLAUDE.md): JS `<script setup>`, logical RTL props (`ms/me/ps/pe/text-start`), valid Nuxt UI colors only (primary secondary success info warning error neutral), `USkeleton` in `<Transition name="sk">` with the page-scoped `.sk-*` CSS copied from `pages/panel/wallet.vue`, toasts via `useAppToast()` (`success/error/info/warning`), two-tone `font-black` titles, dark: variants.
- Patterns to copy: [LIST] = `pages/panel/tickets/index.vue` (skeleton/content/empty, `UPagination`, filter watch resets page to 1). [MODAL] = `components/panel/inventory/StockAdjustModal.vue` (`UModal :open` + `update:open`, `form.space-y-4 dir=rtl`, cancel `soft neutral` + submit `primary :loading`). [CONFIRM] = `components/panel/DeleteConfirmDialog.vue` (props `open,title,message,itemName,confirmLabel`, emit `confirm`). [TABLE] = DESIGN_SYSTEM "Admin data table" (`components/panel/products/ProductsTable.vue`). [DETAIL] = `pages/panel/tickets/[id].vue`. [SHARED-ROLE] = tickets: `const isStaff = computed(() => getUserRole() !== 'customer')`.
- Do not create a `foo.vue` next to a `foo/` folder under `pages/panel/` (it turns `foo.vue` into a parent that needs `<NuxtPage/>`; see the orders move in pages/panel/CLAUDE.md). Use `foo/index.vue`.
- Enum labels: each feature gets `utils/<x>Meta.js` exporting `{CODE:{label,color}}` maps + helper, like `utils/ticketMeta.js`.

### 1.3 Money unit (decision D1)
Order/quote/checkout figures are shown by the storefront as Toman via `formatPrice` directly (cart.vue, CustomerOrders). Payment transaction amounts and wallet top-up are Rial (`*10` in wallet.vue, `/10` in checkout/result.vue). Backend javadocs call shipping `cost/freeShippingThreshold`, gateway `?amount=`, wallet adjust, refunds "ریال". Rule until D1 is answered: storefront shows backend numbers exactly as the existing cart/orders do (`formatPrice`), and every ADMIN money input is labelled «ریال» exactly as BACK documents, with no conversion. Ask the user to confirm the unit once (it affects C3 FIXED value, C4, C6 adjust, C1 refunds, B2).
