# components/ (top-level, auth/, dashboard/)

Covers `components/*.vue` top-level, `components/auth/`, `components/dashboard/{admin,customer,owner}/`. See [`components/panel/CLAUDE.md`](panel/CLAUDE.md) for the panel-management components.

## Purpose
Global presentational and feature components for the public storefront shell (header/footer/hero/product grids, AI chatbot widget), the phone/OTP/password authentication flow, and the role-based `/panel/dashboard` views (admin, owner, customer).

## Key files
- `Header.vue` — sticky nav; cart dropdown (Teleport to body), mobile menu, dark-mode toggle, auth-aware profile button.
- `HeaderSearch.vue` — **new (2026-11-02)**: the navbar search, mounted by `Header.vue` in place of the old dead icon. Icon toggles a panel (`absolute` under the icon on `sm:`, `fixed` full-width on mobile) with an input; typing (**2026-11-04**: 300 ms debounce, min 2 characters, stale responses dropped by a request counter) calls the light `$api.search.suggestGoods` (`GET api/elastic/suggest?q=`, typo/prefix tolerant, rate-limited with 429) and lists up to 5 rows (image, name, brand — the suggest DTO has no price/stock) linking to `/medications/{groupId ?? id}`; loading skeletons and a "محصولی یافت نشد" state. Errors (incl. 429) are silent: the list empties and the CTA still opens the listing. A CTA sits under every non-empty state: "مشاهده همه نتایج" → `/medications?search=<text>` when there are hits, "مشاهده همه محصولات" → `/medications` when there are none (there is no `/products` route). Enter goes to the listing; Esc, outside click, a link click or any route change closes it. Note `Header`'s `backdrop-blur` makes it the containing block for the mobile `fixed` panel.
- `BrandLogo.vue` — the single source of the capsule logo mark + Persian-only "کپسول" wordmark; props `size` (px, default 40), `showName`, `textClass`, `forceDark` (always-dark footer). Used by `Header.vue` (desktop + mobile menu), `Footer.vue`, `pages/panel.vue`.
- `Footer.vue` — static footer, no script logic.
- `CaptchaField.vue` — **new (2026-11-10, B8a)**: captcha block for public forms. v-model `{captchaId, captchaAnswer}`; props `subject` (phone for per-user counting, empty for contact), `audience` (default `STOREFRONT`), `error`. Calls `$api.auth.getCaptchaStatus` on mount and when `subject`/`audience` change; visible only when `enabled && required` or forced; a failed status call = hidden. Image (`data URI`) + numeric `UInput` (`dir="ltr"`) + refresh button; auto-refreshes `expiresInSeconds - 30` s after load; timer and in-flight calls cleared on unmount. Exposes `reset()` (new challenge, answer cleared) and `force()` (show it + load one if missing; shares an in-flight load with `reset()`). Gotcha: an auto-refresh also clears a typed answer.
- `StoreLocationCard.vue` — **(2026-11-01)** map card for the physical pharmacy: OpenStreetMap iframe (no key; Neshan SDK was tried and dropped) + direction buttons (Neshan / Google Maps / Waze), data from `utils/storeLocation.js`. Used on `/contact`.
- `HeroSection.vue` — landing hero text + search box; embeds `HeroCarousel`.
- `HeroCarousel.vue` — self-contained autoplay/swipe carousel, no store/API deps.
- `CategoriesCarousel.vue` — scrollable category chips; navigates to `/medications?category=...`.
- `FeaturedProducts.vue` / `PopularMedications.vue` — hardcoded product/medication grids; render `ProductCard`/`UCard`.
- `ProductCard.vue` — reusable product tile (**rewritten as `<script setup>` 2026-11-02**): is itself the `NuxtLink` to `/medications/{linkId ?? id}`, shows the real image (`product.image`), "از …" price for products with variants, strike-through + `٪ تخفیف` badge, `expiryLabel` notice, and uses valid color tokens. Used by `ProductGrid` (and the legacy `FeaturedProducts`).
- `ProductGrid.vue` — **new (2026-11-02)**: skeleton (`h-96`, `sk` transition) → grid → empty state (props `products`, `loading`, `skeletonCount`, `emptyIcon/Title/Text`, `gridClass`; slot `empty-action`; emits `addToCart`). Shared by home, listing, brand, near-expiry and related rows.
- `HomeSections.vue` — **new**: `GET api/storefront/home` → one titled `ProductGrid` per section, own loading/failed/empty states. `BrandsStrip.vue` — **new**: `GET api/storefront/brands?limit=12` horizontal strip, hides itself on empty/failed.
- `SearchFilters.vue` — **new**: the `/medications` filter card (a single-choice category group on top when `useStoreCategories()` has a tree). Props `state` (from `utils/searchQuery.js::parseSearchQuery`), `facets` (`AttributeFacetDTO[]`), `brands`, `loading`; emits `change(nextState)` (page reset to 1) — it never touches the router itself. Checkbox groups for options/boolean facets, min–max inputs for NUMBER facets (apply on blur/enter, Persian digits accepted).

Shows the logged-in user's pending terms (`usePendingTerms`) with `htmlToText` content (never `v-html`), a checkbox gating «پذیرش», and «خروج از حساب» (`logoutAndResetAuthentication`). ## Public surface
- `ProductCard` — prop `product: Object` (required; build it with `utils/storefrontGoods.js::toProductCard`); emits `addToCart` (camelCase — note casing when wiring listeners elsewhere, which mostly use kebab-case). The card swallows its own button click (`preventDefault`/`stopPropagation`) so it doesn't follow the link — wire add-to-cart with `useAddToCart()`, which sends a `hasVariants` card to its product page instead.
- `AuthModal` — props `modelValue: Boolean`, `redirectAfterAuth: String`; emits `update:modelValue`, `authenticated`.
- `auth/PhoneStep` — props `phoneNumber`, `loading`; emits `update:phoneNumber`, `submit`.
- `auth/PasswordStep` — props `password`, `error`, `loading`; emits `update:password`, `update:error`, `submit`, `switchToOtp`, `forgotPassword`, `goBack`.
- `auth/OtpStep` — props `digits` (array), `error`, `timer`, `loading`, `context` (`'login'|'register'|'forgot-password'`); emits `update:digits`, `update:error`, `submit`, `resend`, `switchToPassword`, `goBack`; exposes `focusFirst()` via `defineExpose`. "Switch to password" button only shown when `context === 'login'`.
- `auth/RegisterStep` / `ResetPasswordStep` — prop `form: Object` (required, must contain an `errors` sub-object the component mutates directly), `loading`; emit `update:form`, `submit`, `goBack`. **B9 (2026-11-10)**: a live tick/cross list of the store's password rules sits under the password field (`composables/usePasswordRules.js`); the rules' `validate()` runs after the existing checks in submit validation and overrides `errors.password`.
- `auth/AuthHero` — no props, decorative only, hidden below `md:`.
- `dashboard/customer/*` — accept `loading: Boolean` + data props, emit `track`/`shop`/`viewAll`/`upload`/`add` (`order`, previously `RefillReminders.vue`'s emit, no longer exists — that component was removed).
- `AdminDashboard`/`OwnerDashboard` — no props/emits; read their composables directly (see Key files).
- Composables read: `useCustomerDashboard`, `useFormat` (`DashboardStats`/`ReorderGrid`), `useUserPanelTabs` (used by `pages/panel/dashboard.vue`, not the components themselves).
- Stores read: `useCartStore` (`Header`, `FeaturedProducts`, `ChatbotWidget`, `CustomerDashboard`); `useChatStore` (`ChatbotWidget`, `HeroSection`).
- Services/API: only `pages/login.vue` calls real endpoints via `$api.auth.*` (see [`services/api/CLAUDE.md`](../services/api/CLAUDE.md)) among components in this module; no `components/auth/*`/`dashboard/*` component calls the API directly — `dashboard/*` reads through `useCustomerDashboard`/`useOwnerDashboard`/`useAdminDashboard`, all real as of 2026-10-27. `AuthModal.vue` still only simulates network calls.

## Data flow and dependencies
- `pages/login.vue` is the sole consumer of `components/auth/*`, owning all state and wiring every step's emits; steps swap via a `currentStep` string machine (`phone → password/register → otp-login/otp-register/forgot-password-otp → reset-password`).
- `pages/panel/dashboard.vue` picks `AdminDashboard`/`OwnerDashboard`/`CustomerDashboard` based on `useUserPanelTabs().getUserRole()` — the only role gating in this module; the dashboard components themselves have no auth checks.
- `CustomerDashboard.vue` depends on `useCustomerDashboard` (mocked) and `useCartStore`/`useToast` for add-to-cart actions.
- `Header.vue` depends on `useCartStore`, `useColorMode`, `this.$auth.loggedIn` to route "profile" clicks to `/panel` vs `/login?redirect=/panel`.
- `ChatbotWidget.vue`/`AuthModal.vue` both call `useNuxtApp().$auth.setToken(...)` directly rather than via a dedicated composable.
- `pages/index.vue` (2026-11-02) mounts `HeroSection` (mock copy), `BrandsStrip` and `HomeSections` (real data). `FeaturedProducts`, `PopularMedications` and `StatsSection` are hardcoded mock components that are **no longer mounted** — safe to delete or revive. `CategoriesCarousel` is mounted again, **rewritten as `<script setup>` on `useStoreCategories()`** (top-level categories → `/medications?categoryId=<id>`, icon from the name via `utils/storefrontGoods.js::categoryIcon`); it renders nothing while the category endpoint is not public (see `pages/CLAUDE.md` gotchas). The RTL scroll math was kept as is.

## Gotchas
- **Two parallel, inconsistent auth flows**: the real one (`auth/*` + `pages/login.vue`) and a legacy dead-end one (`AuthModal.vue`, simulated) still mounted from `pages/cart.vue`. Future login-logic edits won't propagate to the cart modal unless both are updated.
- **RTL-specific scroll math**: `CategoriesCarousel`/`HeroCarousel` invert normal LTR scroll-direction logic because the app is RTL — don't "fix" these to look like standard LTR code.
- `RegisterStep`/`ResetPasswordStep` mutate `form.errors` in place via a two-way computed over the `form` prop — passing an object without an `errors` key throws.
- `OtpStep`'s `context` prop drives conditional UI; an unlisted value fails the prop validator (dev warning only, doesn't throw).
- Admin/owner dashboard data is now real (store-wide aggregates only — no per-user scoping on BACK). Customer dashboard (`useCustomerDashboard`) is also now real as of 2026-10-27, scoped to the logged-in customer's own data.
- Role gating is coarse (`admin | owner | else→customer`) and lives in the page, not the dashboard components.
- `ProductCard` emits `addToCart` (camelCase) while the app otherwise uses kebab-case event names — check casing when adding listeners.
- `Header`'s cart dropdown position is computed manually in JS, not CSS/popper.
- **`h-full` on a dashboard card chains up through `pages/panel.vue`'s `<NuxtPage class="h-full" />`** (which falls through onto the page's/dashboard component's root) into the sidebar-vs-main grid stretch — the sidebar nav is usually taller than the dashboard content, so an un-grounded `h-full` on a card makes it balloon to sidebar height with a huge blank area below its content (fixed on `OrderTracking.vue` 2026-10-28 after removing `RefillReminders.vue`'s 2-column grid, which had been accidentally "grounding" the chain by being its own auto-height container). Only add `h-full` to a card root when it's paired with a sibling inside its own grid/flex row to match heights against — never on a lone/full-width card.

- `InfoDocument.vue` (2026-10-29) — generic public text page shell: prop `documents: [{key,title,content,meta?}]`, `loading`, `emptyTitle`; skeleton/empty states; content is plain text (no `v-html`). Used by `terms.vue`/`privacy.vue`/`returns.vue`.
